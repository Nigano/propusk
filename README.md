# Propusk

Just-in-time privileged SSH access to Linux infrastructure with short-lived certificates.

[![CI](https://github.com/Nigano/propusk/actions/workflows/ci.yml/badge.svg)](https://github.com/Nigano/propusk/actions/workflows/ci.yml)
[![License: Apache 2.0](https://img.shields.io/badge/license-Apache%202.0-blue.svg)](LICENSE)

Propusk — выпускная квалификационная работа: система управления временным привилегированным доступом к Linux-инфраструктуре на основе краткоживущих SSH-сертификатов. Проект в разработке.

## Проблема

Администраторы заходят на серверы по постоянным SSH-ключам. Ключи годами лежат в `authorized_keys`, копируются между ноутбуками и не привязаны ни к задаче, ни к сроку. Украденный ключ даёт атакующему бессрочный доступ и свободу перемещаться по сети, а по журналам трудно понять, кто, когда и зачем заходил на сервер.

## Цель

Сократить окно возможностей атакующего: привилегированный доступ выдаётся только по заявке, на конкретные серверы, роль и время, а каждое действие фиксируется в журнале, который нельзя незаметно изменить.

## Как это работает

1. Инженер входит в CLI `propusk` через Keycloak: OIDC, второй фактор TOTP, device flow.
2. Создаёт заявку: серверы, роль, срок и причина.
3. Политика решает, выдать доступ сразу или отправить заявку на согласование.
4. После одобрения OpenBao подписывает открытый ключ инженера: сертификат на 30 минут (не больше 8 часов), номер заявки в key ID, привязка к адресу через source-address.
5. Бастион открывает доступ в nftables на срок сертификата, а серверы доверяют только CA и не принимают постоянные ключи.
6. События пишутся в журнал с цепочкой хешей SHA-256. При отзыве обновляется список отзыва (KRL), активные сессии завершаются.

## Стек

OpenSSH certificates, OpenBao, Keycloak, nftables, Python (FastAPI, Typer), k3s, Helm, Argo CD, OpenTofu, Ansible, Incus, GitHub Actions.

## Структура

- `src/propusk/` — код сервиса и CLI
- `tests/` — тесты
- `docs/` — архитектурные решения (ADR), схемы, материалы ВКР
- `labs/` — заметки по учебным опытам
- `deploy/` — Docker Compose, Helm-чарт, манифесты Argo CD
- `infra/` — OpenTofu и Ansible для стенда
- `policies/` — политики выдачи доступа
- `attacks/` — сценарии атак для эксперимента
- `scripts/` — вспомогательные скрипты
